## 1. 四层验证体系

| 层级 | 名称 | 执行者 | 手段 | 通过标准 |
|---|---|---|---|---|
| **Level 1** | 需求验证 | ChatGPT + Product Owner | 需求评审：实现范围与 PRD/UI 规范逐条比对，确认无增删改 | 范围 100% 对齐，无未确认偏差 |
| **Level 2** | 代码验证 | ChatGPT（审查）+ Trey（自检） | 代码审查：架构分层、规范符合度、红线检查（硬编码文案 / 网络阻塞启动 / 权限超标等） | 审查通过，无红线违规 |
| **Level 3** | 自动化测试 | Trey | 单元测试（CalculatorEngine、Repository、ViewModel）+ Compose UI 测试；纳入构建流程 | 全部通过，核心逻辑有测试覆盖 |
| **Level 4** | 产品体验验证 | Product Owner | 真机 / 模拟器人工验收（对照测试矩阵） | 验收签字，体验符合 PRD |

## 2. 必须覆盖的验证场景

以下场景在对应层级必须被覆盖（用例编号见 TEST-CASE-MATRIX-V1.0.md）：

### 启动与离线
- [ ] 正常启动（TC-001）：直接进入计算器，无 App Bar
- [ ] **离线启动**（TC-002）：飞行模式下冷启动，计算器完全可用，启动不等待网络

### 计算器交互
- [ ] 输入整数（TC-003） / 小数（TC-004）
- [ ] 删除（TC-005）、长按删除（TC-006）、C 清空（TC-007）
- [ ] 四则运算：加（TC-008）/ 减（TC-009）/ 乘（TC-010）/ 除（TC-011）
- [ ] 百分比（TC-012）
- [ ] 即时换算（TC-013）：输入过程中目标货币实时更新，无需按 =

### 货币
- [ ] ⇅ 交换货币（TC-014）
- [ ] 货币选择（TC-015）：仅限 15 种首发货币
- [ ] 汇率缓存（TC-016）：断网后仍能换算，更新时间为缓存时间

### 汇率数据
- [ ] 网络刷新（TC-017）：↻ 成功更新汇率与更新时间
- [ ] 网络失败（TC-018）：失败提示走字符串资源，不影响计算器使用

### 引导与本地化
- [ ] 首次启动引导（TC-019）
- [ ] 六种首发语言（TC-020）：无硬编码文案，货币名称本地化
- [ ] 深色模式（TC-021）：跟随系统浅 / 深，无手动切换入口

### 集成能力
- [ ] Push（TC-022）（场景待 OQ-04 确认后细化）
- [ ] Google Play 官方评价 In-App Review（TC-023）
- [ ] Analytics（TC-024）（事件待 OQ-05 确认后细化）
- [ ] 权限拒绝（TC-025）：拒绝权限后核心功能不受影响

### 发布质量
- [ ] 性能（TC-026 配套）：启动不等待网络、无卡顿（指标待 OQ-10）
- [ ] Release Build（TC-026）：R8/压缩后功能完整
- [ ] AAB（TC-027）：可构建并通过 Play 校验
- [ ] Play 发布前检查（TC-028）：按 GOOGLE-PLAY-RELEASE-REQUIREMENTS-V1.0.md 清单核对

## 3. 验证环境要求

| 维度 | 要求 |
|---|---|
| 设备 | 至少 1 台真机 + 1 个主流尺寸模拟器 |
| 网络态 | 在线 / 飞行模式 / 弱网 三态 |
| 主题 | 系统浅色 + 系统深色 |
| 语言 | 六种首发语言（清单待 OQ-01）+ 默认语言 |

## 4. 验收结论记录

每个 Phase 的验证结果记录在该 Phase 的交付报告中；产品验收结论由 Product Owner 给出（通过 / 打回 + 原因）。
