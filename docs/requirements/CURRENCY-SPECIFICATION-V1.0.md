## 2. 架构约束（红线）

1. **货币逻辑不得写死在 UI**：货币清单、汇率、小数位等必须是数据驱动（数据模型 / 数据源），UI 只做展示
2. **必须支持未来增加货币**：新增货币应只需增加数据配置，不改动计算器与页面结构
3. **货币代码使用标准 ISO 4217**，全链路（模型、缓存、日志）以 3 位字母代码为唯一标识
4. **国旗 / 地区显示必须与货币数据模型分离**：货币实体本身不携带国旗信息；「货币代码 → 国旗/地区图标」为独立的显示映射配置
   - 原因：一种货币可能对应多个地区（如 EUR 对应多国、USD 亦有非美国地区使用），解耦后未来扩展货币或更换图标不影响数据模型
5. **货币显示名称必须支持国际化**：展示给用户的货币名称按系统语言本地化（如 USD 在英文环境显示 "US Dollar"，中文环境显示「美元」）

## 3. 数据模型要求（蓝图，最终以技术设计为准）

```
Currency（货币实体）
├── code: String            // ISO 4217，唯一标识，如 "USD"
├── decimalDigits: Int      // ISO 4217 小数位
└── (不包含国旗、显示名称等展示信息)

CurrencyDisplay（显示映射，独立配置）
├── code: String            // 关联 Currency.code
├── flagRes / regionKey     // 国旗 / 地区图标资源
└── nameKey                 // 本地化名称资源键（或使用系统 ICU 本地化）

ExchangeRate（汇率记录）
├── base: String            // 基准货币代码
├── quote: String           // 目标货币代码
├── rate: BigDecimal        // 汇率值（禁止用 Float/Double 承载金额计算）
└── updatedAt: Instant      // 更新时间（用于底部「汇率更新时间」展示）
```
